# SEO & GitHub Discovery System

This repository treats discoverability as an engineering surface: clear positioning, indexable text, relevant repository metadata, inspectable proof, and shareable artifacts.

## Discovery stack

```text
Identity
  ↓
Primary keywords
  ↓
README title + opening statement
  ↓
Architecture / capability language
  ↓
Project evidence + internal links
  ↓
Repository description + topics
  ↓
GitHub search / topic discovery / external search
  ↓
Profile visit
  ↓
Proof-of-work exploration
  ↓
Contact / follow / opportunity
```

## Primary keyword cluster

Use these terms only where they describe the actual work:

- AI Systems Architect
- AI engineering
- automation engineering
- intelligent products
- AI automation
- developer tooling
- developer experience
- Python automation
- workflow orchestration
- system architecture
- GitHub developer portfolio
- reproducible developer profile

## On-page rules

1. The first screen states **who**, **what**, and **outcome**.
2. Keywords appear naturally in headings and explanatory text rather than as a keyword dump.
3. Every important capability points toward evidence when public evidence exists.
4. Images have descriptive `alt` text.
5. Repository links use descriptive anchor text.
6. Generated SVGs contain semantic `<title>` and `<desc>` metadata.
7. The README stays concise enough to scan while preserving technical depth.
8. Claims and metrics are never invented for search performance.

## Conversion path

```text
DISCOVER
  → understand positioning in seconds
  → see a distinctive visual system
  → identify concrete capabilities
  → inspect shipped systems
  → find contact / opportunity path
```

## Viral/shareability loop

The profile is designed to produce assets people can share without requiring the viewer to understand the implementation first.

```text
Distinctive visual artifact
        ↓
Curiosity
        ↓
Profile click
        ↓
Technical proof
        ↓
Repository exploration
        ↓
Star / follow / share / contact
        ↓
New audience
```

Virality is treated as a consequence of **distinctiveness + usefulness + proof**, not as an excuse for engagement bait.

## Measurement

Track only metrics that can be observed reliably:

| Signal | Meaning | Action |
|---|---|---|
| Profile visits | Discovery | Improve positioning if weak |
| Repository views | Proof interest | Improve project framing |
| Stars / forks | Public usefulness | Improve utility and docs |
| Followers | Persistent interest | Publish stronger systems |
| Inbound opportunities | Business conversion | Improve proof and CTA |

Do not publish invented percentages, rankings, traffic numbers, or performance claims.
