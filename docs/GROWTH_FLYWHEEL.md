# Compounding Growth Flywheel

The profile is a distribution and trust surface for the systems that are actually shipped. Growth must compound from public evidence rather than from inflated personal branding.

## Core flywheel

```text
BUILD
  ↓
SHIP
  ↓
PROVE
  ↓
PRESENT
  ↓
DISCOVER
  ↓
TRUST
  ↓
SHARE / FOLLOW / CONTACT
  ↓
NEW OPPORTUNITIES
  ↓
BETTER PROJECTS + BETTER EVIDENCE
  └──────────────────────────────→ BUILD
```

## Five growth assets

### 1. Identity

A precise, memorable positioning statement makes the right audience self-select.

### 2. Proof

Public repositories, demos, artifacts, benchmarks, and case studies convert claims into evidence.

### 3. Distinctive presentation

The generated command center provides a visual hook while the README remains technically readable.

### 4. Distribution

GitHub profile → repositories → topic discovery → social shares → external references → inbound opportunities.

### 5. Learning

Visitor behavior, recruiter/client feedback, project performance, and repeated friction feed future revisions.

## Virality model

```text
Novelty × Utility × Proof × Shareability × Distribution
```

No single factor is sufficient. A visually novel profile without useful work is decoration. A technically strong repository without a discoverable presentation is under-distributed.

## Compounding rules

- Every new public project should strengthen at least one capability claim.
- Every major claim should eventually gain inspectable evidence.
- Reusable infrastructure should reduce the cost of publishing the next proof artifact.
- Successful visual patterns should become generator modules rather than one-off edits.
- Feedback should change the system, not just the copy.
- Do not optimize for vanity metrics at the expense of technical credibility.

## Content-to-proof loop

```text
Idea
 ↓
Small useful implementation
 ↓
Public repository
 ↓
README + demo + evidence
 ↓
Profile discovery
 ↓
Feedback
 ↓
Hardening
 ↓
Larger system
```

This makes the profile a **portfolio of systems** rather than a static portfolio page.
